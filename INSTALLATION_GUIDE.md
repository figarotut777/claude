## 🖥️ Системные требования

- **Python:** версия 3.10 или выше
- **Git:** для клонирования репозитория

## 🔑 Получение API ключа Wildberries

API ключ необходим для получения данных о продажах, заказах и остатках с серверов Wildberries.

### Пошаговая инструкция:

1. **Войдите в личный кабинет продавца Wildberries:**
   🔗 [https://seller.wildberries.ru/](https://seller.wildberries.ru/)

2. **Перейдите в раздел настроек API:**
   **Настройки** → **Доступ к API** → **Создать новый токен**

3. **Выберите необходимые права доступа:**
   - ✅ **Статистика** (чтение) - для получения данных о продажах
   - ✅ **Контент** (чтение) - для получения информации о товарах
   - ✅ **Marketplace** (чтение) - для получения остатков

4. **Скопируйте сгенерированный API ключ**
   ⚠️ **Важно:** API ключ показывается только один раз! Сохраните его в надёжном месте.

5. **Пример API ключа:**
   ```
   eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJhY2Nlc3NJRCI6IjEyMzQ1Njc4...
   ```

## ⚙️ Настройка конфигурации

### Шаг 1: Создание файла .env

```bash
# Скопируйте пример конфигурации
cp .env.example .env
```

### Шаг 2: Редактирование .env

Откройте файл `.env` в любом текстовом редакторе:

```bash
nano .env
# или
vim .env
# или откройте в VS Code, Sublime Text и т.д.
```

### Шаг 3: Установка параметров

```env
# ===== ОБЯЗАТЕЛЬНЫЙ ПАРАМЕТР =====
# Ваш API ключ Wildberries (полученный на предыдущем шаге)
WB_API_KEY=ваш_api_ключ_wildberries_здесь

# ===== ОПЦИОНАЛЬНЫЕ ПАРАМЕТРЫ =====
# Путь к базе данных SQLite (создаётся автоматически)
DB_PATH=wb_analytics/data/wb_analytics.db

# Настройки веб-сервера
PORT=5000                    # Порт для доступа к дашборду
DEBUG=False                  # True - для отладки, False - для продакшена

# Логирование
LOG_LEVEL=INFO              # DEBUG, INFO, WARNING, ERROR
LOG_FILE=wb_analytics/logs/app.log

# Настройки синхронизации
INITIAL_SYNC_DAYS=30        # Сколько дней истории загружать при первом запуске
DATA_RETENTION_DAYS=90      # Сколько дней хранить старые данные

# Финансовые настройки
DEFAULT_WB_COMMISSION=15.0  # Комиссия WB по умолчанию (%)
```

**Пример заполненного .env:**

```env
WB_API_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJhY2Nlc3NJRCI6IjEyMzQ1Njc4...
DB_PATH=wb_analytics/data/wb_analytics.db
PORT=5000
DEBUG=False
LOG_LEVEL=INFO
INITIAL_SYNC_DAYS=30
DATA_RETENTION_DAYS=90
DEFAULT_WB_COMMISSION=15.0
```

## 🎬 Первичная инициализация

Перед первым запуском необходимо инициализировать базу данных и загрузить исторические данные.

### Запуск скрипта setup.py:

```bash
python scripts/setup.py
```

### Что происходит при инициализации:

1. ✅ **Проверка подключения к Wildberries API**
   - Валидация API ключа
   - Проверка прав доступа

2. ✅ **Создание структуры базы данных SQLite**
   - Таблица `products` - информация о товарах
   - Таблица `sales` - продажи и заказы
   - Таблица `stock` - остатки на складах
   - Таблица `sku_cost_price` - история себестоимости
   - Таблица `settings` - системные настройки

3. ✅ **Загрузка данных за последние 30 дней** (по умолчанию)
   - Продажи и заказы
   - Остатки товаров
   - Информация о товарах (названия, артикулы, бренды)

4. ✅ **Вывод статистики**
   - Количество загруженных товаров
   - Общее количество продаж
   - Период данных

### Пример успешного вывода:


## 🔄 Настройка автоматического обновления (опционально)

Для автоматического обновления данных каждый час настройте cron (Linux/macOS) или Task Scheduler (Windows).

### Linux/macOS: Настройка cron

```bash
# Сделайте скрипт исполняемым
chmod +x scripts/setup_cron.sh

# Запустите настройку cron
bash scripts/setup_cron.sh
```

Скрипт добавит задачу в cron, которая будет запускаться каждый час:

```bash
0 * * * * cd /полный/путь/к/wb_analytics && python scripts/sync_data.py >> logs/cron.log 2>&1
```

### Проверка cron задачи:

```bash
crontab -l
```

### Ручная синхронизация данных:

В любой момент можно запустить синхронизацию вручную:

```bash
python scripts/sync_data.py
```

### Windows: Task Scheduler

1. Откройте **Task Scheduler** (Планировщик задач)
2. Создайте новую задачу:
   - **Триггер:** Повторять каждый час
   - **Действие:** Запуск программы
   - **Программа:** `python`
   - **Аргументы:** `/полный/путь/к/wb_analytics/scripts/sync_data.py`

## 🐛 Устранение неполадок

### Проблема 1: "ModuleNotFoundError: No module named 'flask'"

**Причина:** Зависимости не установлены или виртуальное окружение не активировано.

**Решение:**
```bash
# Активируйте виртуальное окружение
source venv/bin/activate  # Linux/macOS
venv\Scripts\activate     # Windows

# Установите зависимости
pip install -r requirements.txt
```

---

### Проблема 2: "Address already in use" (порт занят)

**Причина:** Порт 5000 уже используется другим приложением.

**Решение 1:** Измените порт в `.env`:
```env
PORT=8080  # или любой другой свободный порт
```

**Решение 2:** Найдите и остановите процесс, использующий порт 5000:
```bash
# Linux/macOS
lsof -ti:5000 | xargs kill -9

# Windows
netstat -ano | findstr :5000
taskkill /PID <PID> /F
```

---

### Проблема 3: "sqlite3.OperationalError: database is locked"

**Причина:** База данных заблокирована другим процессом.

**Решение:**
```bash
# Остановите все процессы, использующие БД
pkill -f "python.*server.py"
pkill -f "python.*sync_data.py"

# Перезапустите сервер
python scripts/start_server.py
```

---

### Проблема 4: Дашборд показывает "N/A" для всех метрик

**Причина:** Данные не загружены или себестоимость не указана.

**Решение:**
1. Проверьте, что синхронизация прошла успешно:
   ```bash
   python scripts/sync_data.py
   ```

2. Укажите себестоимость для товаров через дашборд:
   - Нажмите кнопку "✏️" в таблице товаров
   - Введите себестоимость (COGS)
   - Сохраните изменения

3. Установите налоговую ставку:
   - В верхней части дашборда выберите УСН 4% или 6%
   - Метрики пересчитаются автоматически

---

### Проблема 5: "Invalid API key" при инициализации

**Причина:** Неверный или устаревший API ключ.

**Решение:**
1. Проверьте API ключ в `.env` (нет лишних пробелов, ключ полный)
2. Сгенерируйте новый API ключ в личном кабинете WB
3. Обновите `.env` с новым ключом
4. Повторите инициализацию:
   ```bash
   python scripts/setup.py
   ```

---

### Проблема 6: Cron не работает

**Проверка:**
```bash
# Проверьте список cron задач
crontab -l

# Проверьте логи cron
tail -f logs/cron.log

# Проверьте системные логи (Ubuntu/Debian)
grep CRON /var/log/syslog
```

**Решение:**
1. Убедитесь, что пути в cron задаче абсолютные (не относительные)
2. Проверьте права доступа к скриптам:
   ```bash
   chmod +x scripts/sync_data.py
   ```
3. Активируйте виртуальное окружение в cron задаче:
   ```bash
   0 * * * * cd /path/to/wb_analytics && source venv/bin/activate && python scripts/sync_data.py
   ```
